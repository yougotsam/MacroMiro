risk.ts

/workspace/src/lib/desk/risk.ts

Last check before a send. Refuses run in this order.

R1

Product

In the file nowAnything that is not an event contract is refused. The reason string is perps disabled.

Option, not appliedKeep the door shut, or open a second product with its own cap.

R2

The order itself

In the file nowPrice, fee, and tick id must be finite. Fee cannot be negative. Tick id must be an integer.

Option, not appliedKeep.

R3

Three switches

In the file nowkalshi_live off, kalshi_begin off, or ARM off. Each one refuses on its own.

Option, not appliedCollapse to the arm switch only.

R4

Watchdog

In the file nowIf the watchdog pulse is bad, new entries are refused.

Option, not appliedKeep.

R5

Snapshot

In the file nowMissing, stale, negative totals, from another ET day, or the exchange is not trading: refuse. Exchange status older than 15 seconds counts as paused.

Option, not appliedKeep.

R6

Day stop

In the file nowIf a latch is already stored, refuse. If today's worst case is through the day stop, latch it and refuse. Worst case is realized minus open, resting, and unconfirmed sends.

Option, not appliedA smaller number. Or a latch that stays until you turn it off by hand.

R7

Loss-count pause

In the file nowstreakPauseUntil still runs. It only fires if losses reach LOSS_STREAK_PAUSE, which is 9999. A win resets the count. Losses inside an existing pause do not add.

Option, not appliedDelete the function, or set the count to 3.

R8

Settled-loss pause

In the file nowsettledLossPauseUntil takes the most recent losing settlement at or before now. If that time plus 20 minutes is still ahead, refuse. A later win does not erase a loss still inside the 20 minutes.

Option, not appliedSame choices as C7. This is the line that enforces it.

R9

Identity and band

In the file nowTicker must match the 11-series pattern. Count at least 1. Price inside PRICE_MIN and PRICE_MAX.

Option, not appliedSame choices as C1 and C9.

R10

Dollars

In the file nowOrder cost including fee ≤ per-order cap. The day must remain above the day stop after the order. Open plus resting plus unconfirmed plus this order ≤ total cap.

Option, not appliedSame choices as C3.

R11

One live order per window

In the file nowIf ticker exposure maps are missing, refuse. If any ticker in this same window id already has worst-case exposure above zero, refuse. The reason is one live order per window. A cancel that left the book does not count.

Option, not appliedOne order per series instead of per window. Or no window cap.

R12

Groups

In the file nowThat ticker's worst case, including this order, must be ≤ $3. Same-direction crypto across coins must be ≤ $4. Gold is its own group. A non-number refuses.

Option, not appliedOne cap for the whole book. Or a separate cap per coin.

R13

Counts and cash

In the file nowOrders already recorded on that exact ticker must be under the per-ticker cap, which is 1. Orders already sent this engine tick must be under 1. Cash on the paying shard must cover the order.

Option, not appliedKeep both counts at one.
